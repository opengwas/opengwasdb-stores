Release config

The one connector file written per Store Release (#287).

Governed by ADR 0036: a source plugs into Manifest Generation through four files. Three belong to the Source Collection – the Acquisition Manifest, the Source Metadata Table and the Column Map (source connectors) – and the fourth, the release config, belongs to one Store Release. It names everything the shared pipeline needs that is not the Source Collection’s: the release’s identity, the Selection, the Build Recipe shape, the release policy and its Quality Check overrides, the Reference Resources, and the collection-wide defaults.

Contract Owner
Schema and loader src/manifest_generation/release_config.py (load_release_config)
Selection grammar src/manifest_generation/selection.py (spec)
Quality Check names and thresholds src/manifest_generation/quality_checks.py
Indexed Variant Subset default src/manifest_generation/indexed_subsets.py

Loading is a gate. An unknown key at any level, a missing required field, a value outside its vocabulary, a Reference Resource reference that names no declared resource (or one of the wrong kind), and the legacy Selection grammar are refused, each by name. Nothing is ignored and no required fact is defaulted. A relative path is relative to the repository root.

A config states release_config_version: 1. A file without it predates this schema: the generator configs that produced the committed bundles (config-full.yaml, config-pilot-10.yaml, …) are kept unchanged as the history their bundles’ generator.commands cite, and are refused here by that key.

Keys

Key Required Description
release_config_version Yes 1.
label Yes Source-natural release name, written to release.yaml. Never an identifier.
association_coverage Yes What associations the Store holds, written to release.yaml right after label:, in one vocabulary with opengwasdb (issue #341, ADR 0040): gwas, cis, cis_and_signals or signals_only. It is declared, never inferred from the Store Layout. A region-filtered config must declare the coverage its region_policy.association_coverage names, so the two cannot disagree.
access_posture No public, controlled or embargoed; public only when the key is absent, so an explicit false or blank is refused.
trial No true for a Trial Store Release: a deliberately small release that exercises a Source Collection, Source Format or Store Layout (#321). It must be a YAML boolean, so a quoted "yes", a number or null is refused. true writes trial: true to release.yaml (the schema). Absent or false writes no key, which means false, so such a release renders exactly as before the key existed. Every shipped pilot and probe config sets it.
description Yes Prose for release.yaml.
notes No Prose; the candidate’s own evidence notes follow it in release.yaml.
source_collection Yes The Source Collection and its files (below).
selection Yes The Selection, in #283’s grammar: exactly one of all: true, analyses: [...] or where: {...}, with an optional expect_rows membership bound.
build Yes The Build Recipe shape build.yaml carries (below).
completion No For a reference-completed release, the recipe and the LD panel it completes against (below, #340, ADR 0037).
indexed_subsets, indexed_subsets_opt_out No Dense and Hybrid releases declare the maintained hm3 Indexed Variant Subset by default; [] with a reason opts out; a Ragged release declares none (stores #210).
defaults Yes Collection-wide Analytical Metadata defaults and the method tiers (below).
release_policy Yes Membership policy inputs (below).
quality_checks No Quality Check threshold overrides: a registered check’s name to its threshold for this release (#285).
reference_resources Yes The Reference Resources the run uses (below).
ancestry_assignment Yes What Analysis Resolution measures ancestry against (below).
effect_scale_validation No Phenotype-SD evidence settings (below).
trait_ontology_mapping Yes The Canonical Trait Mapping Table (below).
column_map No; required exactly when build.options.source-reader-capability is opengwasdb.column-map The Column Map the release reads its sources through: builtin: <name> or path: <file>, one of the two (below, #292).
region_policy No For a region-filtered release, the regions acquisition filters its files to (below, #300).
runtime No cores (default 1, capped at 64 by preflight) and min_free_gb (default 0).
output Yes work_root: the root of the Store Release’s Work Root, absolute or repository-relative like every path here. The resolution root is deployment configuration and output.resolution_root is refused (#284).

source_collection

Key Required Description
source_collection_id Yes One path segment; names the Resolution Area.
connectors.source_metadata_table, connectors.acquisition_manifest No; both or neither The connector files freeze reads. Absent when the config names only an already frozen inventory.
inventory.snapshot_id Yes The frozen Source Inventory’s snapshot id.
inventory.directory Yes Where it is: <directory>/<snapshot_id>.tsv, .meta.yaml and the two frozen connector files (freeze).

The pipeline’s freeze stage writes the inventory from the connectors when it does not exist, and otherwise checks that the existing one was frozen for this Source Collection and this Selection. A frozen inventory is never overwritten: a re-freeze is a new snapshot id.

build

layout, completion_state, command and post are required, options is not. completion_state is observed_only or reference_completed; a reference_completed config declares the completion block that says what it completes against, and an observed_only one declares none (below). command names an opengwasdb subcommand and options are its flags, passed through verbatim (ADR 0023): options is opaque by design, and its keys are not checked here. post is the registry’s own vocabulary – top_hits, overview, rho and validate, each true or false, the steps ogstores.plan plans – so an unknown key or a non-boolean is refused. An indexed_subsets entry takes only the Release Bundle contract’s keys (name, resource_id, variant_list, reference_assembly, checksum, options). The recipe carries no artifact root (#126). Manifest Generation reads two options itself: source-reader-capability (the reader the resolver uses; default opengwasdb.gwas-ssf, and opengwasdb.besd for build-ragged-besd, which reads one format and takes no such flag) and variant-reference (the Variant Reference the resolver measures overlap against).

completion

A release that is completed against an LD reference panel declares the recipe and the reference (#340, ADR 0037). One Store id is published twice: the build block publishes the Observed-Only Store, and the completion phase reads that published Store and replaces it, so no second id is minted and no derived_from is claimed. src/manifest_generation/completion.py owns this vocabulary.

Key Required Description
reference.resource_id Yes A declared ld_panel Reference Resource (below).
reference.qualification Yes The owner’s: qualified, pending, hold or not_applicable.
reference.activation Yes The panel’s usability on this host: active, pending or blocked.
command Yes complete-dense. ADR 0037’s Observed-View Check also covers the Dense Component of Hybrid Stores; this pipeline emits Dense completion only so far, which is why no other command is accepted here.
options No The complete-dense flags beside the panel, passed through verbatim (ADR 0023). ld-panel and ancestry are refused here: they are the Reference Resource’s.

The reference’s declared status is not a key here. It is the Reference Resource declaration’s own status (available), read from its resource.yaml and recorded, and it is kept apart from qualification and activation: a declared status is neither, and a config that restates one is refused as an unknown key.

The bundle completes its Store only when the reference is qualified and active. Then build.yaml declares completion_state: reference_completed, build and complete, and release.yaml carries no derived_from; the build block is exactly the Observed-Only one, so completing a published Store schedules no rebuild (ADR 0037 clarified by #305). Anything short of that – pending, hold, blocked – emits the Observed-Only bundle a config with no completion block emits, and records why: the release notes say the recipe is blocked, and validation.yaml’s acceptance.completion_reference carries the declared reference with blocked: true. A blocked recipe is not an error: the release is still emitted, as the Observed-Only Store it is ready to be.

What the recipe cannot contradict, each refused by name:

  • a layout other than dense (see above);
  • a complete-dense option naming the panel;
  • the reference’s ancestry, from its declaration, differing from release_policy.selection_superpopulation: completion imputes against a panel for the Store’s Assigned Ancestry;
  • a declaration whose ancestry_dir is not its ancestry, because complete-dense names both the panel directory and the Analyses it completes with one --ancestry (#219);
  • a qualified, active reference whose declaration records no status: the status is recorded as it is, and never defaulted;
  • build.completion_state: reference_completed with no completion block, and observed_only with one;
  • the retired completed_store_id / planned_completed_store_id (ADR 0007’s second id, which ADR 0037 removes).

The panel is resolved only when the reference is qualified and active. Then its location is the reference_resources entry’s, which preflight requires present, and its status, ancestry and ancestry_dir are the declaration’s, so the recipe cannot name a panel other than the one the resource declares. A blocked reference is never opened: its declaration need not exist, its panel need not be present, and no panel need be declared at all – so a blocked recipe still emits the Observed-Only bundle on a host that has no panel.

build:
  layout: dense
  completion_state: reference_completed
  command: build-dense-vcf
  options:
    source-reader-capability: opengwasdb.gwas-vcf
    source-assembly: hg19
    n-workers: 32
  post:
    top_hits: true
    overview: true

reference_resources:
  - resource_id: ukb-hg38-eur-ld
    kind: ld_panel
    location: /data/opengwasdb/reference/ld
    location_kind: external_directory
  # ... the ancestry mixture and the Canonical Trait Mapping Table

completion:
  reference:
    resource_id: ukb-hg38-eur-ld
    qualification: qualified
    activation: active
  command: complete-dense
  options:
    n-workers: 32

ukb-hg38-eur-ld’s declaration (resources/reference-resources/ukb-hg38-eur-ld/resource.yaml) supplies its ancestry: EUR and ancestry_dir: EUR, so the emitted complete block is {"command": complete-dense, "options": {ld-panel: /data/opengwasdb/reference/ld, ancestry: EUR, n-workers: 32}}.

defaults

Key Required Description
by_study_design Yes One method tier per study_design, each with stored_effect_scale, original_effect_scale, original_sd_method and sample_size_kind. stored_effect_scale, original_sd_method and sample_size_kind must be in OpenGWASDB’s vocabularies (opengwasdb.model.enums, imported, not copied); original_effect_scale has no closed vocabulary. A ready Analysis whose design has no tier fails preflight.
source_genome_build No GRCh37 or GRCh38.
license, publication_doi, consortium No Text.
sample_size_scope No OpenGWASDB’s SampleSizeScope; default analysis_level.
analysis_group_id No Default blank.
info_score_threshold No The INFO floor in [0,1] a declared Analysis requests; default 0.6 (#175).
maf_threshold No The MAF floor in [0,0.5] each Analysis requests; absent is no MAF filter (#176).
tissue, context No The measured tissue and assay context (plasma, SomaScan), as analyses.tsv carries them (#300).

A tier’s sample_size_kind decides whether the Analysis carries case/control counts: case_control keeps its n_cases/n_controls and requires both, and any other kind leaves them blank (analyses.tsv’s absence rule, #133). The tier’s stored_effect_scale decides the SD handling instead – a non-quantitative scale asks for no phenotype SD and emits binary_trait. The two are separate because a Source can pair them either way: ukb-b’s binary traits are on the SD scale (units: SD) with a case/control sample size, so its case-control tier declares stored_effect_scale: sd beside sample_size_kind: case_control (#289).

source_genome_build, license, publication_doi, consortium, tissue and context are release-wide facts: an Analysis whose Source Metadata Table row carries a value keeps it, and one whose cell is blank takes the default. A metadata adapter never writes a collection-wide fact into the table (#283). Each Analysis’s source_genome_build, taken this way, is also the build its resolver manifest row declares; the resolver is never given a --source-build fallback (opengwasdb#277).

release_policy

Key Required Description
selection_superpopulation Yes The super-population code (AFR AMR EAS EUR MID NAF SAS) the Selection expects, or multi-ancestry for a Selection that names none (#290). The assigned_ancestry Quality Check tests each Assigned Ancestry against it; it never moves an Analysis (ADR 0036). multi-ancestry makes that check not_applicable: the measured fit is recorded and never assigned, so the emitted Assigned Ancestry stays empty with method unassigned and no Analysis is excluded for ancestry.
store_composition.require_maf_filtered No The Store Composition Rule (ADR 0033). Needs a positive defaults.maf_threshold.
trust_source_ancestry_without_af No true opts in to #287’s decision for sources with no allele frequencies (Sun 2018): an Analysis whose Resolution Record shows ancestry unmeasurable for that reason takes its Source Metadata Table source_superpopulation as Assigned Ancestry (source_trusted_no_af), a warning-level assigned_ancestry result. The record shows it only under a MAF request, so the opt-in needs defaults.maf_threshold (0 filters nothing): the resolver then counts every row without a usable frequency (maf_rows_missing), and absence is every row it read (canonical_rows_observed) with no ancestry site. Default false: such an Analysis is ancestry_unassigned. A measured ancestry never takes the source label, and frequencies the fit could not read (palindromic sites, unusable standard errors) are not absent.
keep_unassigned_ancestry_as_warning No true opts in to #290’s decision: an Analysis the ancestry gates left unassigned (Assigned Ancestry empty in its Resolution Record, with frequencies it could read) stays in, unassigned – Ancestry Assignment Method unassigned, a warning-level assigned_ancestry result counted in validation.yaml and recorded per Analysis in the Quality Check sidecar. Default false: it is excluded as ancestry_unassigned. A measured different super-population still excludes as ancestry_not_eur, and the opt-in is refused in a multi-ancestry Selection, which never assigns ancestry.
imputation_score_declarations No The reviewed per-Analysis INFO score declarations (#175). The table is the Source Collection’s, so Selections may share it: a declaration may name an Analysis outside the Selection when the collection intends it (the original Source Metadata Table the snapshot’s provenance checksums), and only the Selection’s apply. A declaration the collection does not intend is refused, and so is one outside the Selection when that table is not on the host.
maf_filter_exempt_genotyping_technologies No Technologies exempt from the MAF floor (#176). Policy over a fact: an Analysis is exempt when its Source Metadata Table genotyping_technology is non-empty and every technology it lists is named here. The column records what the source says and never decides exemption; a blank column is never exempt, and shared code reads no source metadata file (#347).
maf_filter_exempt_analyses No The reviewed per-Analysis MAF-floor exemptions (#176).
effect_placeholder_exclusions No The reviewed effect-placeholder listing the effect_placeholder_rows Quality Check reads (#285).

region_policy

A region-filtered release – Chen 2023, Sun 2018 – keeps only the regions its policy names, and acquisition applies it: download, filter, delete the original, recording the policy in each filtered file’s lineage (ADR 0036 clarified by #300, region-filtered acquisition). The policy is per release config.

Key Required Description
region_policy_id Yes The policy’s name, recorded in lineage (sig-trans-1mb_suggestive-leads).
association_coverage Yes signals_only, or cis_and_signals to keep a cis flank around each Analysis’s target.
cis_flank_bp For cis_and_signals only Bases kept either side of the Source Metadata Table’s target span (target_chromosome, target_start, target_end); refused for signals_only.
trans_flank_bp Yes Bases kept either side of every significant row outside the cis window.
significant_p, suggestive_p Yes p-values in (0, 1]; significant_p may not exceed suggestive_p.
suggestive_lead_min_distance_bp Yes How far apart, strictly more than, the suggestive leads kept on one chromosome are.
qc_panel_resource_id Yes A declared qc_panel Reference Resource, whose positions every filtered file keeps so Analysis Resolution can measure ancestry and SD. Preflight requires it present.

association_coverage is one of the policy’s, not a free choice: the release’s top-level association_coverage must name the same value, because a policy is what filters the acquisition and the bundle declares what the Store holds.

The frozen acquisition must have been filtered to exactly this policy: preflight and rendering refuse a file whose lineage records another policy, another QC panel sha256 or another target span, a policy declared over unfiltered files, and region-filtered files under a config that declares no region_policy (source connectors).

column_map

A release that reads its sources through the opengwasdb.column-map Source Reader Capability names its Column Map, and no other release may: build.options.source-reader-capability: opengwasdb.column-map and a column_map block go together, and either without the other is refused.

  • builtin is the name of a map OpenGWASDB ships (gwas-ssf, finngen-r13).
  • path is a map file this release carries, absolute or repository-relative. Its file name must be a valid column_maps/ file name (a .toml name of the Indexed Variant Subset grammar).

The resolver is passed it as --column-map, a built-in’s name or the file’s path. build.yaml binds it as column_map: {name, sha256, file}, with no file for a built-in, and a carried map is copied into the bundle’s column_maps/. name and sha256 are what OpenGWASDB records as each Resolution Record’s resolution_config.column_map, so a built-in’s checksum is the file the pinned package ships. The checksum is part of the resolution contract: a changed map makes every Resolution Record stale and the resolver re-resolves them. The Column Map’s contract and how Store Release Build uses it are in Source connectors and the release metadata schema.

Reference Resources

reference_resources lists each resource the run uses: resource_id, kind and location are required; location_kind, version, status, fine_group_map, ancestry, super_populations, genome_build and variant_id_convention are optional. A resource_id declared twice is refused. Four blocks use them, by id:

  • ancestry_assignment.reference_resource_id (required) names the ancestry mixture the resolver measures against: an ancestry_mixture resource, with a fine_group_map. The resolver’s --reference-build is the genome_build of that resource’s declaration, resources/reference-resources/<id>/resource.yaml, not of this entry; a missing declaration or genome_build is refused, because the resolver never guesses a build (opengwasdb#277). liftover_chain_resource_id (optional) names the chain the resolver lifts a source build that differs from that reference build with: a liftover_chain resource, whose declaration states its from_genome_build, to_genome_build and sha256. The resolver is passed --chain-file for its location; a chain whose to_genome_build is not the reference build is refused when the settings are composed, because that is a declaration. The file’s own bytes are checked before the resolve stage starts the resolver: a chain that is absent, or whose sha256 is not the declared one, refuses the run by name. Without a chain the resolver refuses a source on another build. The declared checksum is part of the resolution contract, and it is the declared one that the settings digest covers – composing a run’s settings reads no liftover chain file, so a config whose chain lives under /data still composes on a CI runner that has no /data. maf_floor (default 0.01), extraction_panel (default none) and gates (tau 0.50, delta 0.20, n_min 5000, residual_max 0.06) are passed to the resolver as written.
  • effect_scale_validation.reference_resources lists {ancestry, resource_id} reference-AF resources for phenotype-SD estimation. maf_min, maf_max and dispersion_max are recorded in sidecars/sd_estimation.tsv; dispersion_max (default 0.5) marks a high-dispersion estimate.
  • trait_ontology_mapping.reference_resource_id (required) names the Canonical Trait Mapping Table, a trait_ontology_mapping resource whose location is its resource directory (#286).
  • completion.reference.resource_id names the LD panel a reference-completed release completes against: an ld_panel resource whose location is the panel root and whose declaration names its status, ancestry and ancestry_dir (#340).

Preflight requires every named resource to be present.

Pilot prefixes

A pre-#287 pilot selected a deterministic prefix with n_analyses (“the first 10 case-control Analyses of the pool”). The Selection grammar adds no prefix form: a migrated pilot writes the Analyses out as an analyses: list. A prefix depends on the order of the Source Metadata Table, which a re-run metadata adapter may change, so it would select different Analyses from the same config; a list selects the same ones until a reviewer edits it, and the reviewer sees exactly which.
