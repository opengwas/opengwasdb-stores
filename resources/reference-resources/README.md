# Reference Resources

Reference Resources describe auxiliary build-time resources such as LD reference panels and genome references. They can be used by Build Recipes but are not the summary-statistics Source Collections that define Store Families.

Each subdirectory records one Reference Resource declaration (`resource.yaml`): a stable `resource_id`, ancestry/population label, genome build, variant identifier/allele conventions, and a `location` for the resource data. Build Recipes reference a declared `resource_id` (see `docs/release-metadata-schema.md`, "Reference Resource declaration") so reviewers know exactly which panel a release used. Most panels here are multi-GB and live under the configured artifact/reference root, never in this repository; `qc-panel-hg38` is the one exception, small enough to track directly (see below).

- `ukb-hg38-eur-af/` - UKB hg38 EUR reference allele frequencies, used as the reference-AF fallback for effect-scale validation (issue #16) when a Source Collection provides no usable source allele frequencies.
- `ukb-ancestry-mixture-hg38/` - UK Biobank ancestry-mixture reference allele frequencies (Privé 2022), used for AF-based ancestry assignment (issue #23) when a Source Collection provides usable source allele frequencies. Distinct from `ukb-hg38-eur-af`: this one is multi-ancestry (7 super-populations) and used for mixture fitting, not single-ancestry MAF lookup. It also tracks `source_label_map.tsv`, the free-text Source Ancestry Label -> super-population translation the manifest generators read so Assigned Ancestry stays in one vocabulary (issue #133), and its companion `source_label_imprecise.tsv`, the labels that map leaves out on purpose, each with a reason, so an unknown label is refused rather than left blank (#283).
- `qc-panel-hg38/` - a fixed 10,000-variant QC panel derived from `ukb-ancestry-mixture-hg38`, common in every super-population and spread across the genome (issue #28/#29). Unlike the two resources above, this one's panel file (`qc_panel.tsv`, ~450 KB) is tracked directly in this repository rather than pointing at external storage. Every region policy keeps it unconditionally (regardless of significance; `release_config.region_policy.qc_panel_resource_id`, #300; the retired R generators' `filter.qc_panel`, issue #30), giving ancestry assignment and effect-scale validation a stable variant backbone independent of how many significant hits a given Analysis has.
- `gpm-hg38-eur-ld/` - UKB hg38 EUR LD reference panel, used for reference completion of EUR-assigned Analyses. Declares the same physical directory as `ukb-hg38-eur-af`, but for its LD content rather than its allele frequencies.
- `ukb-hg38-eur-ld/` - the same UKB hg38 EUR LD panel as it is on this host, at `/data/opengwasdb/reference/ld` (on disk as `ukb/`, reached through the `EUR -> ukb` alias complete-dense's `--ancestry EUR` needs). The owner-approved completion panel for UKB-B, OGS-00009 (#219, #312), and for the dbGaP MVP EUR Store, OGS-00012 (#227); `gpm-hg38-eur-ld`'s location is the generation host's and is absent here.
- `hgdp1kgp-hg38-ld/` - available HGDP+1kGP LD reference panels for AFR, EAS and SAS. Built from a different, much smaller cohort than the EUR panel; see ADR 0020 for why, and for the resulting permanent difference in completion quality across ancestries. Held for reference completion on #348, which found duplicated variant identities within their blocks, so no Store completes against them yet.
- `hgdp1kgp-hg38-eur-calibration/` - available matched, non-production EUR calibration control; its quantitative comparison with the UKB EUR panel passes its exploratory gate and recommends shipping the production panels, which is no longer the open question: #348 holds them.
- `hapmap3-hg38/` - the maintained HapMap3 GRCh38 canonical ALID list (1,206,903 rows, `kind: variant_list`), the build input for the default `hm3` Indexed Variant Subset (epic #214, ticket #208). The 18.9 MB list and the unmodified LDSC source snapshot live outside Git under the reference root; `resource.yaml` records the source provenance, row count, source checksum and derived-ALID checksum, and `verify_hm3_resource.py` refuses a missing, malformed, duplicate, non-canonical, wrong-length or checksum-mismatched copy. See its README for the rsID reconciliation and the #209 consumer contract.
- `canonical-trait-mapping-efo/` - a curated `trait_label` -> `trait_ontology_id`/`trait_ontology_label` exact-match lookup, consulted by Manifest Generators when a Source Collection doesn't supply its own trait ontology mapping (issue: Trait Ontology Mapping). Tracked directly in this repository, like `qc-panel-hg38`; starts empty pending real curated rows.

Generation and maintenance tooling for LD panels lives in `tools/ld-panel/`, and
the other resources' build and verify scripts in
`tools/reference-resources/<resource_id>/`: this directory holds inputs only
(ADR 0038).
