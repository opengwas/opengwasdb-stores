- **The staged-publication routes share one owner for the resolver-mismatch rule, the leftover refusal and the SIGTERM handler (#520).** `staged_publication.republication` applies `register`'s resolver-mismatch warning once, so `publish-rewrite` and the in-place post-addition route write the same `checks.store` and `status` as a `register` run (an in-place addition no longer raises `checks.store` to `passed_with_warnings`). `staged_publication.refuse_leftovers` is the one leftover refusal, with one message and the union of both routes' checks, and `staged_publication.publish` turns SIGTERM into Ctrl-C itself, so a library call rolls back too. `register_release` reads earlier records through `run.read_record`, so an unreadable one is refused, not read as missing; the `run`/`register` alias names are gone.
