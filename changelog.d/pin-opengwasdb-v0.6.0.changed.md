- **The `opengwasdb` engine moves from `v0.5.0` (`42850d8`) to `v0.6.0` (`4b72e2f`), the merge of opengwasdb PR #397 (epic opengwas/opengwasdb#58).** The Store format stays 0.2.0, so the release guard's `REQUIRED_FORMAT_VERSION` does not move. What changes for this repository:
  - `register` reads the `findings` list `validate --format json` now prints beside `ok`, `errors` and `warnings` (opengwas/opengwasdb#378). It checks every item, and that `errors` and `warnings` are exactly its error and warning messages in order, and still reads the three-key verdict an older engine wrote. A skipped rule moves no verdict and is not recorded in `validation.yaml`.
  - A Variant Reference artifact extracted before `v0.6.0`, whose routing column is `source_keys`, is refused by every reader at the new engine (opengwas/opengwasdb#354), the Store Audit's included. The `variant-reference` pre-stage now refuses such a file at its destination instead of skipping it as `provided` (ADR 0031, amended): it writes a failed record, runs nothing and deletes nothing, and deleting the file lets the next run extract it again. No bundle declares the pre-stage, and every reference a bundle names is a plain ALID list or a Store Variant Table, which read as before.
  - `build-ragged-ssf` lifts a row that declares GRCh37, given the recipe options `chain-file` and `liftover-failure-threshold`, which `plan()` renders like any other, and refuses only a row that declares no build (opengwas/opengwasdb#386). That replaces `v0.5.0`'s "builds only rows that declare GRCh38". All 4,453 rows of the five committed Ragged SSF bundles declare GRCh38, so none names either option. Every builder's Admission record now reads rules `admission/11`, which adds the reasons `lift_unmapped` and `lift_ambiguous`.
  - Every rsid harvest applies one test of a disputed name (opengwas/opengwasdb#379). A `build-hybrid --reference-panel` build reports `rsid_conflicts` counts where it reported `null`, and accepts `drop`; `build-dense-vcf`, `build-ragged-ssf` and `extract-variant-reference` refuse a site its sources spell two ways under two rsids. The engine measured no published Store whose names change or that would refuse to rebuild.
  - `query --format json` rows carry `eaf` and `association_status` and are valid JSON: `null` for a value that is not there, and the strings `"Infinity"` and `"-Infinity"` for an infinite one (opengwas/opengwasdb#394). The query walkthrough shows them, and its `association_status` filter now reads the TSV's last column (`$NF`), which is where that column always is: a numbered one breaks under `--variant-info` and on a Store with an `n` plane.
  - `build-dense` takes `--manifest` and one association TSV per Analysis (opengwas/opengwasdb#385). No step here plans it; the LD-panel comparison's test fixture builds through it.
