- **The `opengwasdb` engine moves from `v0.6.0` (`4b72e2f`) to `v0.7.1` (`89e1a26`).** The Store format stays 0.2.0, so the release guard's `REQUIRED_FORMAT_VERSION` does not move. What changes for this repository:
  - `complete-ragged` codes a residual-SE Store's cells against the source's `se_coefficients` instead of refitting them, so every observed SE comes through completion exactly and the strict Ragged Observed-View Check passes such a pair (opengwasdb `v0.6.2`, opengwas/opengwasdb#301). That unblocks completing OGS-00006 under its own id (#224). A completed Ragged Store's manifest also records `provenance.completion.se_exceptions`: each Analysis's SE exception rate, and the Analyses over the 2% budget, which completion names in a warning. `docs/runtime.md`, ADR 0037 and the release-workflow spec no longer say completion refits SE.
  - `complete-ragged` takes `--n-workers`, the LD-block process-pool size, as `complete-dense` and `complete-hybrid` do (`v0.7.0`). A bundle's `complete` block can now name it; before, every Ragged completion this workflow ran completed its blocks in one process.
  - `v0.7.1` checks the length of completion's carried mask and has the exact-carry rule predict from the frequency a reader decodes with. No Store's bytes change.
