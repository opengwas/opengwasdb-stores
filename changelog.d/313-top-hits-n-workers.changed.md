- **`build-dense-top-hits --n-workers` and a completion step's `--n-workers` are documented (opengwasdb#313, #321, stores#358).** `build-dense-top-hits` sizes its scan's process pool with the flag, and the index does not depend on the count (OGS-00003's took 46.5 s at one worker and 7.3 s at 32); a Dense build plans no standalone step any more (stores#357), so an operator passes it when running the command by hand on an existing Dense Store. `docs/spec/store-release-workflow.md` also says that a completion step's `--n-workers` sizes the LD-block, checkpoint-merge and write pools (opengwasdb#321).
