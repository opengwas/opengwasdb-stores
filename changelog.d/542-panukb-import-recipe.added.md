- **Pan-UKB LD Stores are imported from this repository, and the import writes their record (#542, epic #496).** `pixi run ld-stores import --ancestry EUR --metadata … --variants … --chain … --fasta … --work <work> --out <store> --ld-id OGL-NNNNN` runs ogld#10's `opengwasdb ld import` command line, validates the Store once, and writes its record with a runnable `rebuild` that names the four inputs in a new optional `rebuild.inputs`. The writer pins each input's sha256 from the Store's own `source.sha256`, and refuses a digest that is not the Store's or a path its commands do not read. Every ancestry but EUR is refused, naming ogld#104. `--plan-only` runs the engine's new `opengwasdb ld import --plan-only` alone (the plan and lifted tables, no network, no record); an engine without the option is refused by name, from its CLI's own "No such option" error. `pixi run ld-stores rebuild OGL-NNNNN --out <dir> --plan-only` re-plans a recorded import, and `pixi run ld-stores compare-plan <plan.json> <reference.json>` compares two plans chromosome by chromosome (parts, losses, far_bp, source_variants, the Store's far_bp and the input digests), failing on every difference but the output path. OGL-00012's `rebuild` is now runnable: #10's own `ogld import` and `ogld validate`, at `opengwas/ogld` 0.8.0 and 0.8.1, relocated to the Store's location, with its inputs. An imported matrix's rebuild is accepted on the field-by-field comparison alone, since it is not an HGDP+1kGP Store. The Hail variant export stays in opengwasdb.
