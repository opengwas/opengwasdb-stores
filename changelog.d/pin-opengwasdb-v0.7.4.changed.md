- **The `opengwasdb` engine moves from `v0.7.1` (`89e1a26`) to `v0.7.4` (`f2ddb0f`).** The Store format stays 0.2.0, so the release guard's `REQUIRED_FORMAT_VERSION` does not move. What changes for this repository:
  - `complete-ragged`'s Phase 3 (merge, assembly and write) now streams through Dense completion's on-disk fill shards and `RaggedCSRWriter`, instead of holding the whole completed Store in memory (opengwas/opengwasdb#424). OGS-00006's first completion (#224) was stopped because its 10.0B fills would have needed about 1.7 TB on a 1 TB host; its Phase 3 now projects to about 4 h with a peak near 222 GiB. Checkpoints keep format 2, and what a completion writes is unchanged, with one fix: an Analysis carried through unchanged is written in variant order, where `v0.7.1` could write it unsorted, which `validate` refuses.
  - `v0.7.2` and `v0.7.3` change only the engine's contributor rules and quality baselines. No Store's bytes change.
