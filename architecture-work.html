Work map

Which work is changing which part of the system right now, and where two owners’ work meets on one component. An owner is an epic, or a branch or ticket that is on no epic of the board.

See also the Pipeline.

Written by hand: which code each component owns (the claims in each repository’s docs/architecture/components.yaml), the epics and tickets on the board and the blocking edges between them, and the files a ticket’s text cites. The claims are in the repositories, the rest on the project board.

Measured: the files each live branch changes, which component each file and each cited file falls on, the state of each piece of work there, and the meets between owners. Nothing measured is written by hand, so it cannot drift from the code.

What the states mean

  • building: a branch’s diff against the merge-base with main
  • active: a file cited by an open ticket of an Active epic
  • waiting: a file cited by an open ticket that waits for another open ticket
  • scope: a file cited by an epic’s body
  • planned: a file cited by an open ticket of a Todo epic
  • paused: a file cited by an open ticket of a Paused epic
  • stale: a branch whose epic or ticket is closed

A meet is two or more owners with building or active work on one component. It is coordinated only when a blocking edge links two specific tickets of the owners, in either direction; sharing an epic, or an edge between other tickets of the same epics, does not count. A meet that involves an epic’s integration branch is unlinkable: the branch belongs to the epic as a whole, so no edge can link it to one ticket, and “uncoordinated” would claim more than was checked.
