Structure and health

How the system fits together at three levels (C4): who and what it talks to, its containers, and the components inside the engine and this repository, with the imports between them.

See also the Pipeline.

Written by hand: the system context, the containers and how they relate, the engine’s layers (the intended layering, a decision rather than a measurement) and the code each component claims. Each is in a repository’s docs/architecture/components.yaml.

Measured: the imports between components (counts, read from the code of both repositories), which of them go against the layering, the seam between the repositories, and the gaps in the claims. Nothing measured is written by hand, so it cannot drift from the code.

Planned changes

The plan is written by hand in the ticket; whether a closed ticket’s plan held is measured against the claims and imports on the ref read. An open ticket’s plan is drawn as planned and not checked.
