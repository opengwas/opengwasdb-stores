Storage format internals

From a VCF row to an 8.9 ms lookup

OpenGWASDB takes per-analysis summary statistics — GWAS-VCF or BESD — and reduces them to two canonical arrays, a choice of physical layout, and a stack of purpose-built indexes. This is that pipeline end to end, grounded in the actual eQTLGen and UK Biobank benchmark runs.

01

What comes in

Two source formats reach the same canonical shape. GWAS-VCF carries one analysis per file; BESD carries a whole matrix of analyses (probes) per file set.

GWAS-VCF recordper variant · per analysis
  • CHROM, POSgenomic coordinate, hg19 or hg38
  • REF, ALTalleles, oriented to canonical ALID on read
  • EZz-score, preferred when present
  • ES, SEeffect + standard error, fallback for z
  • ##SAMPLEStudyType header → stored effect scale
BESD triple.esi + .epi + .besd
  • .esi rowchr, snp_id, bp, a1, a2, freq — shared variant list
  • .epi rowchr, probe_id, bp, gene, orientation — one per analysis
  • .besdbinary column table: snp_index[], beta[f32], se[f32]
02

What gets kept

Every source field collapses into one canonical statistic pair, plus a small set of values that only need to be known once per analysis or once per variant — never once per cell.

Arrives as

betasez / ez eaf / freqninfo rsidstudy type
→

Canonical pair, per cell

zse

beta is never stored — it's recovered as z × se on read. Scale-agnostic, and avoids the undefined beta/z case when z is exactly zero.

Everything else moves to a coarser grain, or drops entirely. EAF is Variant-scoped, filled only where a reference panel supplies it — not stored per association. Sample size is typically Analysis-scoped, one value for the whole column. INFO is optional and Absent by default. None of the three is required to reconstruct beta, SE, Z, or p-value — that's the boundary the format is drawn on. — ADR-0005
03

Where the cells live

Same z/se pair, two physical shapes — chosen by whether analyses share a variant axis or each keep their own retained set. (Illustrative grid below; real stores range from hundreds of thousands to tens of millions of variants.)

Dense

Shared variant × analysis matrix

e.g. UK Biobank GWAS batches — every analysis reports on ~the same variants
  • Address a cellz[row, col] — O(1)
  • Missing cellNaN, no extra storage
  • Costdivergent analyses waste NaN cells
Ragged

Per-analysis retained sequence

e.g. eQTL/pQTL — each analysis keeps a different cis window
  • Address a celloffsets[i]…offsets[i+1], binary search
  • Missing cellnot represented at all
  • Costno shared column alignment across analyses
04

Filling in against a reference panel

An Observed-Only release holds exactly what the source reported. Reference Completion is a separate, later pass: LD-block elastic-net imputation fills variants the source never observed, and every cell keeps a status.

Observed — from the source
Imputed — inferred from the LD panel
Missing — not observed, imputation declined or out of scope

Observed-Only

sparse — only what the source reported

Reference-Completed

same axis, gaps filled where the quality gate passes
Every imputed cell carries provenance, not just a value. A completion_quality row records the Pearson r of the fit, n_imputed, and n_missing at LD-block × Analysis granularity. For Dense stores specifically, n_missing splits further: n_missing_off_panel (source-only variants with no LD structure — never imputable, tracked once per Analysis) versus n_missing_imputation_failed (reference-panel variants where the fit didn't clear the quality gate).

What sits alongside z and se

None of these change what a query returns — each one exists purely to avoid a full scan for a specific access pattern.

Variant axis
variants.tsv.gz + .tbi

BGZF byte offset per variant_index — jump straight to one row, no scan

mmap'd, sorted — binary search a variant by identity, ~zero process startup cost
by ALID
O(log n), ~0MB RSS

top_hits/p_5e_08, p_5e_06, p_5e_04
Precomputed, threshold-parameterised — significance queries skip the full matrix
tophits

Imputed mask
data.zarr/imputed (Reference-Completed only)
Parallel uint8 array — drives Association Status and observed_only filtering inline
status lookup
O(1), no join

besdq, by comparison, resolves identity through an in-memory dict — O(1) but ≈1.5 GB resident at 12M variants. The mmap'd index trades a constant factor for near-zero startup memory.
